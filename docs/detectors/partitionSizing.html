Partition sizing

Shuffle partitions are too large, too uneven or too few, so tasks spill or fail.

Outcome

Where you see it

Dashboard

The PART tag marks it in the action region of the dashboard, among the widgets that rank a fix. Every affected stage is flagged, not only the worst.How to read it in the findings guide.

CI (CLI)

List this entry from the command line. The output below is a real run of the command. Budgets and exit codes are in the CI guide. 

sparkforensics-analyze detectors --type partitionSizing --format md
# Detectors (1)

## Speed

| Tag | Type | Scope | Fix | Gate | What it finds |
| --- | --- | --- | --- | --- | --- |
| PART | `partitionSizing` | stage | config |  | Shuffle partitions are too large, too uneven or too few, so tasks spill or fail. |

Report only this finding type for a run with --type:

sparkforensics-analyze <event-log> --type partitionSizing --impact critical,warning,info

It has no budget flag. Fail a build on a new one by comparing against a baseline with --fail-on-introduced.

Airflow

The operator has no budget parameter for it. Use fail_on_introduced with a baseline.

check_spark_job = SparkForensicsOperator(
    task_id="check_spark_job",
    log_source=...,
    backend=SubprocessAnalyzeHook(),
    baseline_log_source=...,
    fail_on_introduced="critical",
)

The operator works per run, and its summary counts findings per impact band. See the operator for its parameters.

How it is measured

Thresholds

A shuffle partition over 5× the median or over 5 GiB, or 1 GiB of shuffle on 7 tasks or fewer.
